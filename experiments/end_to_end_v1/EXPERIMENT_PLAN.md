## 1. 研究问题与定位

主实验比较完整 AeroWeaver 与不同类别的任务执行系统，回答：在相同任务、环境和测试初始条件下，结合技能激活、分布式局部决策与奖励引导经验复用的 AeroWeaver，能取得怎样的任务收益，其推理与交互开销是多少？

不预设 AeroWeaver 在所有任务上超过训练后的 MARL。预先关注任务收益与资源开销的共同表现，允许出现任务间差异。完整系统对比不能单独证明某个组件的因果作用；技能激活、通信与决策组织、在线经验更新的作用分别交给后续三组消融。

推荐论文顺序为 End-to-End Comparison、Component Ablations。后者内部围绕三个贡献展开，不再把三组消融当作外部方法对比的替代。

## 2. 环境与任务

统一使用当前 Mock 环境，不另搭一套 MPE 动力学。`backend/sim/mock_rewards.py` 将 Mock 状态映射给 `mpe2==1.1.0` 的奖励函数；其 manifest 明确记录 `native_mpe_rollout=False`。因此实验应称为 MPE-inspired Mock tasks with MPE2 reward-function adaptations，不能称为原生 MPE benchmark 成绩。

| 主任务 | 固定角色配置 | 主要考察内容 | 奖励函数来源 |
| --- | --- | --- | --- |
| 协同覆盖 `coverage` | 3 个被测 agent、3 个目标地标 | 分散覆盖目标、减少重复占位与碰撞 | `simple_spread` |
| 追逐逃避 `pursuit` | 3 个被测 pursuer、1 个固定策略 evader | 局部观察下的联合追逐与拦截 | `simple_tag` |
| 异质信息协同 `world_communication` | 1 个被测 leader、2 个被测 pursuer、2 个固定策略 forager | 不同信息范围与角色职责下的协同 | `simple_world_comm` |

环境中的 leader 是会运动、会执行动作的任务参与者，不是 AeroWeaver 的 Commander。必须核对它的额外观测信息确实受环境角色定义约束。

每个任务使用未见过的布局、初始位置和随机种子。追逐与异质信息任务中的对手对所有方法保持相同策略、参数和随机数流；首版采用冻结的现有策略。更换对手或扩大机群规模作为单列的扩展测试，不能混入主表后择优汇报。

前三类任务是首版主实验范围，不代表九宫格中的全部任务已验证。若论文最终主张覆盖全部九类任务，应补齐评测，或明确其他任务仅展示环境支持形式。保留当前先导结果不佳的 `world_communication`，不能依据结果删除它。

### 时间与奖励口径

- 开发集起始配置：物理步长 0.05 s，每 10 个物理步决策一次，即 0.5 s/轮；120 轮对应最多 60 s 仿真时间。正式值在开发集校准后统一锁定。
- 决策前所有方法观察同一时刻的状态，所有动作提交后统一推进世界，避免请求顺序改变物理轨迹。模型等待时间不偷偷增加某一方法的仿真时间。
- 当前记录器在决策区间结束时计算一次奖励。主实验沿用这个采样单位，不把 10 个物理步误记成 10 条决策轨迹，也不混用区间奖励与逐物理步奖励。
- 主指标使用未折扣回合回报。记忆中的回报使用决策区间为单位的 `gamma=0.95`；所有方法读取相同奖励，不添加新的边界、探索或通信奖励塑形。
- 完成与超时的条件跨方法一致；结束后采用统一吸收终态、后续奖励为零，以固定最大时域定义回报。必须核查提前终止是否改变任务排名，并同时记录实际结束时间。
- 捕获诊断与奖励函数接触计分可能不同，分别保存定义，不能将 Mock 的捕获成功率称为 MPE 原生成功率。

## 3. 对照组

| 方法 | 类型与来源 | 在本实验中的配置 |
| --- | --- | --- |
| Centralized LLM + API | 自建工程基线，不是外部论文算法 | 一个 LLM 读取被测团队可观测信息的并集，通过完整任务 API 集合给出联合动作；无任务级技能激活、无跨回合奖励记忆 |
| HMAS-2 (adapted) | 外部 LLM 多机器人方法 | 保留中央计划、局部反馈、中央修订的交互结构，适配当前动作接口与观测；不用 AeroWeaver 的激活与奖励重排序 |
| MAPPO (adapted) | 外部 MARL 方法 | 在同一 Mock 任务重新训练；集中式 critic 用于训练，执行时各 actor 只接收其允许的局部信息 |
| MADDPG (adapted) | 外部 MARL 方法 | 在同一 Mock 任务重新训练；训练使用集中式 critic，部署采用局部 actor |
| AeroWeaver | 完整方法 | 任务整体技能激活、角色与机体绑定的局部决策、可达 peer 消息、角色索引记忆、奖励优势驱动的技能重排序全部开启 |

HMAS-2 的原论文不是 MPE 实验，必须标注 adapted，不宣称原论文提供了本环境成绩。其中央计划交由局部 agent 反馈、迭代后输出计划的结构可由作者项目核实。[HMAS-2 作者项目](https://yongchao98.github.io/MIT-REALM-Multi-Robot/)

MAPPO 的官方实现包含 MPE 支持，可作为算法与训练配置的来源；需检查参数共享是否适合 leader/pursuer 异质角色，不能默认把所有角色当成完全同质个体。[MAPPO 官方实现](https://github.com/marlbenchmark/on-policy)

MADDPG 面向合作与竞争多智能体任务，适合提供经典非 LLM 对照。改用新框架实现时须核对 actor、critic、目标网络和更新规则，不只保留算法名称。[MADDPG 论文](https://arxiv.org/abs/1706.02275)

### 动作接口与控制器公平性

三个 LLM 系统共享相同任务操作能力、参数空间和底层执行器。普通 API 基线直接读取 API 名称与参数说明，AeroWeaver 读取技能描述并执行任务级激活；不能故意给 API 基线缺失的能力或损坏的 schema。HMAS-2 保留原方法的计划反馈结构，迁移只处理环境接口。

MARL 主对照使用明确的运动与通信动作接口，在同一动力学、速度上限和决策频率下学习。其动作不得偷偷经过 AeroWeaver 的追逐启发式，从而把不同算法变成同一个控制器；也不能让 MARL 获得更差的执行带宽而不披露。

当前 Mock 技能执行器包含追逐、避让等控制先验。因此完整系统结果包含这些先验的收益，并非纯 LLM 与神经策略能力对比。应补充 `MAPPO-Skill` 作为共享技能执行器的控制实验：使用同一完整技能集合与执行器，仅由学习策略代替 LLM 选择。它是适配变体，不冒充原始 MAPPO。未完成该控制实验前，不将主表差异归因于 LLM 规划能力优于 MARL。

集中式 LLM 可以汇聚己方合法观测，但不能直接读取隐藏目标、对手内部状态或世界真值。MAPPO/MADDPG 的 critic 可在训练中使用集中信息，测试 actor 不可使用；它们本身不是集中式运行时基线。

peer 消息带宽、可达半径、传输延迟和到达时刻需要统一规定。对 LLM 的文本和 MARL 的向量分别记录负载大小，不能把任意长文本与少量通信维度当作天然等价的信道。中央汇聚所需的数据传输也计入系统成本；通信优势另用同基座消融验证。

## 4. 训练、经验积累与留出测试

### 数据分离

已有实验 1-2 的轨迹可用于开发检索、调参数和定位错误，不直接作为首版主实验唯一提供给 AeroWeaver 的隐形先验。现有 20260909-193743 批次及已经人工查看的种子全部列入开发集。正式训练、经验积累和留出测试使用互不重叠的种子清单及可复现布局生成器。

各方法接收同一结构化任务与角色配置。主实验从任务配置确认后到完成/超时计分，自然语言场景解析准确率单独评估；不能让解析错误改变角色数量，导致不同方法实际运行不同任务。

### 建议规模

每个任务、每个方法采用 5 个独立训练/运行重复。MARL 对应 5 个独立训练种子；AeroWeaver 对应 5 个相互隔离的经验库与运行重复。

1. **训练与开发**：MARL 在训练分布内学习；LLM 提示、激活参数、检索参数与 beta 只在开发集确定。所有 LLM 对照使用同一实际服务的模型 ID、版本、采样配置；以请求日志核实 DeepSeek 基座，不依赖 UI 展示名。
2. **经验积累**：每个重复执行 10 个新回合。AeroWeaver 从空任务经验库开始边执行边更新，其他方法按各自规定运行，同样记录轨迹。积累阶段本身也保留完整回报曲线，不能作为不计成本的隐藏预热。
3. **主测试**：每个重复执行 20 个留出回合，共 100 个测试回合/方法/任务。每个留出回合从该重复积累阶段结束后的同一记忆快照启动，可在本回合内更新记忆，但本回合数据不得进入下一个留出回合。MARL 测试权重冻结。这样完整方法仍可在线更新，同时测试布局之间不互相污染。

五方法、三任务合计 1,500 个主测试回合，加 750 个经验积累回合，共 2,250 个回合，不含 MARL 离线训练、开发试跑和补充控制实验。增加到 10 个独立重复时合计 4,500 个回合；最终数量需在查看正式结果前按预算锁定。

5 个独立训练/记忆库重复不等于 100 个独立算法训练样本。先按这个规模估计效应及不确定性，不承诺足够统计功效；开发试跑后可做基于方差的样本量估计，再锁定正式数量，不能根据正式结果是否显著决定追加回合。

### 经验与训练约束

- 记忆按 experiment、split、scenario、controlled team、role、episode 索引。重复之间隔离，禁止将对手轨迹或其他方法的留出轨迹自动作为当前方法的可检索经验。
- 检索仅使用当前决策之前可用的数据；进行中回合只能使用已观测奖励形成的部分回报，完成后再补齐最终折扣回报。不能把整条轨迹最终回报回填后用于重放早期选择，并宣称是在线决策。
- 日志保存检索条目、可见截止时间、base score、经验优势、beta、更新分数与实际执行技能。无匹配经验时优势为零。
- MARL 的离线训练预算不是那 10 个积累回合。建议从每任务每训练种子 1M 个联合环境决策步开展开发校准，查看训练/验证曲线后决定正式预算或统一扩展上限。训练不足就不能将结果描述为有竞争力的算法上限。
- 离线训练步数、调参配置数、模型预训练来源、经验回合数与 GPU/API 开销分别披露。固定权重 MARL 测试只代表该部署设置，不能据此声称 MARL 不支持持续学习或 AeroWeaver 已超过微调方法。

## 5. 指标与统计

### 主指标

按任务分别报告被测团队成员的平均未折扣回合回报：先对各成员整回合奖励求和，再对被测成员求平均。合作共享奖励也采用平均，不重复求和放大机群规模收益。对抗双方不相加；leader 与 pursuer 的分角色回报另存明细。

不直接平均三个任务的原始奖励来产生一个总分，因为量纲与奖励尺度不同。未预定义可靠二值完成条件的任务不编造成功率。

### 次指标

| 指标 | 定义与用途 |
| --- | --- |
| 覆盖完成率、碰撞 | 使用冻结的 Mock 诊断阈值，辅助解释覆盖回报 |
| 捕获率、到捕获时间 | 使用冻结的捕获条件；未捕获视为删失，不能只对成功回合平均时间 |
| 分角色回报 | 检查 leader/pursuer 或不同职责的收益是否失衡 |
| 总 token、调用数 | 从任务准备到结束计入激活、中央反馈迭代、局部决策及重试 |
| 团队决策 p50/p95 延迟 | 按每轮全部必要调用的关键路径计时，包含检索、通信、执行调度等待 |
| 通信量 | peer 消息与中央信息汇聚分别统计消息数和字节量 |
| 异常率 | 非法输出、超时、fallback、调用失败均保留，不删除对应回合 |
| 训练与积累成本 | MARL 环境步和 GPU 时间、LLM 积累回合及 token 单独列示 |

LLM 基线使用相同的团队级输出预算规则，不以“每个 agent 相同预算”忽略多 agent 总消耗。HMAS-2 的多轮反馈计入预算，不能为省预算移除其核心交互后仍沿用原名称。具体上限先经开发集确认能完成必要交互，再冻结；报告实际用量而非仅报告上限。

配对条件包括任务、布局种子、对手随机数流和重复编号。先计算每个独立重复内的平均配对回报差，再报告跨重复的均值、标准差与区间；可补充分层 bootstrap，重采样单位先是独立重复，再是其内部的配对回合。不得把时间步或同一记忆库内回合当作独立训练种子。

若做显著性检验，预先限定三个任务上 AeroWeaver 对四个基线的 12 个主比较并进行 Holm 校正；小样本以效应量、区间和逐重复结果为主，不以单个 p 值证明全面领先。

## 6. 主表和配图

主表建议每行一个方法，列为三个任务的回报及不确定性。训练预算、每回合 token、决策延迟作为紧凑副表或效率图，避免主表同时塞进所有诊断指标。

配图用三个子图分别展示每项任务的回报与在线成本关系，附误差区间。不得把 MARL 的零 API token 表示成零计算成本；其 GPU 推理与训练资源单独记录。经验积累阶段的曲线用于展示完整系统随使用的表现，奖励更新的净效应仍由第三组消融确认。

汇报所有预定任务、种子及失败。可以用成功案例帮助解释行为，但主表不能筛选“有提升”的回合，也不能将当前先导的技能调用结果替代完整闭环回报。

## 7. 正式运行前的必要检查

- [ ] 验证 Mock 的完整在线更新路径。当前 `backend/sim/mock_task_api.py` 报告 online updates off，`backend/memory/mock_trajectory.py` 写入 `reuse_allowed=False`、`online_update=False`，尚不足以证明完整方法已接入。
- [ ] 先完成无付费调用的小测试：相同状态和 base score 下，高回报相关经验能按公式改变选择；不匹配角色和未来经验不改变选择；beta 为零时与原选择一致。
- [ ] 核实候选分数来源与覆盖范围。不把 LLM 自报置信度、缺失 logprob 的均匀补值称为真实模型 logits；若采用显式技能选择器分数，应如实定义并与论文保持一致。
- [ ] 候选选择使用稳定 skill/option ID，解决先导实验的索引越界问题；fallback 的实际动作、奖励与错误一并存储。
- [ ] 对外部算法检查动作、观测、终止、奖励采样及 actor/critic 信息权限；完成基础收敛与接口回归测试。
- [ ] 冻结技能清单与控制器版本。检查世界通信任务是否因激活遗漏必要技能而形成不合理能力缺失，只在开发集修正，不在正式测试后追改。
- [ ] 检查所有方法的半径、速度、消息延迟与动作持续时间一致；保存初始世界快照与 reward manifest。
- [ ] 用独立开发种子做低成本试跑，测出每回合调用量和耗时；正式预算估算完成后才启动全量任务。
- [ ] 保存锁定后的协议、seed manifest、配置哈希、模型版本与代码版本。未经上述检查，不把现有写入 memory 的轨迹当作完整在线 RL 实验。

## 8. 运行记录与故障处理

建议输出 `run_manifest.json`、`seed_manifest.json`、`episode_metrics.csv`、`role_returns.csv`、`decision_trace.jsonl`、`experience.jsonl`、`retrieval_trace.jsonl`、`training_metrics.csv` 和 `failures.jsonl`，另保存每个重复的记忆快照与模型检查点。

episode 指标应包含 method、scenario、replicate、split、seed、opponent version、memory snapshot hash、reward source、return、termination reason、token、latency、fallback count。选择日志必须能关联到真实执行动作，避免只记录提案而遗漏执行结果。

模型输出错误和推理超时属于被测系统表现，使用统一的保持动作或预定 fallback 后继续，费用与失败均计入。宿主机断电、服务整体不可用等基础设施中断单列，不将缺失回报任意填成零；仅按预先规则从同一初始快照重跑并保留原始尝试。所有运行设置硬预算与硬超时，不无界重试。

## 9. 当前证据与修改边界

现有技能激活先导报告位于 `results/skill-activation-closed-loop/20260909-193743/EXPERIMENT_REPORT.md`。它支持开发决策与成本估算，但实验中的在线更新关闭、时间范围较短，不能支持完整 AeroWeaver 的端到端性能结论。

本方案新增研究设计文档，不改已有结果、不修改论文结论、不启动实验。下一步应先实现并验收完整在线选择路径及基线适配，再冻结正式配置。
